## 1. README: назначение продукта, состав репозитория, быстрый запуск

**Назначение.** «Питомец Финни» — игровой сервис, в котором ребёнок 7–11 лет учится планировать бюджет, различать обязательные и необязательные расходы и копить на цель, заботясь о виртуальном питомце. Каждое финансовое решение (потратить на обязательное, потратить на желаемое, отложить) напрямую влияет на состояние и развитие персонажа, что делает последствия решений наглядными и объяснимыми. Приложение работает полностью офлайн, без аккаунта и без сбора персональных данных.

**Состав репозитория:**

## 2. Требования к окружению и сборка релизного APK

**Инструменты:**

| Инструмент | Версия |
|---|---|
| JDK | 17 (входит в Android Studio) |
| Android SDK | API 34 (платформа `android-34`), Build-Tools из AGP 8.5.0 |
| Gradle | обёртка проекта (wrapper, включён в репозиторий) |
| Android Gradle Plugin | 8.5.0 |
| Kotlin | 2.0.0 (+ Compose plugin, KSP 2.0.0-1.0.22) |

Минимальная версия Android: **8.0 (API 26)** — соответствует аппаратным требованиям ТЗ (раздел 3.1). Целевая версия: API 34.

**Сборка (пошагово):**

```bash
git clone https://github.com/vladimirsokolov10007-creator/Finance_Game.git
cd Finance_Game/Финни_Android
./gradlew :app:assembleDebug       # 1. отладочный APK: app/build/.../app-debug.apk
./gradlew :core:economy:test       # 2. юнит-тесты игровой экономики (23 теста)
./gradlew :app:assembleRelease     # 3. релизный APK
```

Для release-сборки требуется подпись: файл `keystore.properties` (рядом с `app/build.gradle.kts`) с параметрами keystore. Сам keystore и пароли **в репозиторий не включены** (требование 3.4 ТЗ: в репозитории отсутствуют закрытые ключи подписи). Без `keystore.properties` соберётся неподписанный релизный APK.

**Особенность окружения:** если проект лежит в пути с кириллицей (как в рабочей копии автора), JVM Windows читает argfile тестовых worker в CP1251, тогда как Gradle пишет его в UTF-8 — classpath тестов ломается. Поэтому build-директории перенаправлены в ASCII-путь `C:/Users/<user>/.finni_build` (переопределяется `-Pfinni.build.root=...`, см. `build.gradle.kts`). При клонировании в ASCII-путь (рекомендуется, напр. `C:\StudioProjects\Finni`) обход не требуется.

Воспроизводимость сборки подтверждена: релиз v0.6.0 собран из чистого состояния (`BUILD SUCCESSFUL`), тесты 23/23.

## 3. Функциональная и компонентная архитектура

**Стиль:** MVVM, однонаправленный поток данных, внедрение зависимостей Hilt, UI на Jetpack Compose. Серверной части нет (по ТЗ не требуется — раздел 3.2), приложение полностью локально.

**Модули:**

| Модуль | Назначение | Зависимости от Android |
|---|---|---|
| `app` | MainActivity, навигация (Navigation Compose), 14 экранов, ViewModel'и, загрузка JSON-контента | да (Compose) |
| `core:economy` | Чистая игровая логика: BudgetEngine, SavingsEngine, RewardEngine, PetEngine, достижения | нет (чистый Kotlin, юнит-тестируем) |
| `core:data` | Room: сущности, DAO, БД (v3), миграции 1→2→3, ProfileRepository | да |
| `core:design` | FinniTheme, типографика (≥16 sp), кнопки (≥48 dp), общие компоненты | да (Compose) |

**Схема потока:** пользовательское действие → ViewModel → доменный движок (`core:economy`, чистые функции) → запись состояния (Room + SharedPreferences) → обновлённый UiState через `StateFlow` → рекомозиция экрана. Игровая экономика не зависит от UI и БД, что обеспечивает её изолированное тестирование (23 юнит-теста без Android-окружения).

**Экраны (`app/ui`):** Onboarding (знакомство + «Как играть»), CreatePet (питомец: персонаж из 3 скинов, фон из 3 вариантов — 9 комбинаций, имя, возраст 7–9/10–11), Main (питомец, баланс, накопления, цель, показатели, активное задание), Plan (план бюджета на период), Shop (Продукты/Улучшения), Tasks + TaskPlay (обучающие задания), Goals (накопления и цели), History (транзакции), PeriodEnd (итоги периода), Adult (раздел взрослого), GameOver, Victory, Celebration.

**Учебный контент отделён от интерфейсного кода** (требование 3.2): все задания, товары, цели и глоссарий — JSON-файлы в `app/src/main/assets/content/` (15 заданий `tasks.json`, 13 товаров, 3 цели). Добавление контента не требует изменения логики UI.

| `PeriodEntity` | id, profileId, index, план и факт по 3 направлениям (обязательные / желаемые / накопления), adherence (доля соблюдения плана), status |
| `TransactionEntity` | id, profileId, periodIndex, сумма, направление, тип (доход / покупка / пополнение накоплений / снятие / награда), источник — для каждого начисления видны источник и сумма (требование 2.5.4) |

**Игровой цикл:** период = «неделя». Начальный баланс 40 монет; со 2-й недели автоматически начисляется доход 30 монет (в первый период дохода нет — только стартовые 40, решение продукта). Закрытие периода подводит итог план/факт и обновляет состояние питомца.

## 6. Формулы и правила игровой экономики

Вся экономика — чистые функции модуля `core:economy`, поведение зафиксировано юнит-тестами.

**Бюджет и план (BudgetEngine):**

- Допустимость плана: `Σ направлений ≤ balance` (иначе план отклоняется, показывается превышение).
- Остаток: `remainder = balance − Σ направлений`.
- Покупка: отклоняется (`null`), если `price > balance` — баланс не уходит в минус.
- Допуск исполнения: направление считается исполненным, если `|факт − план| ≤ max(план × 0.2; 2)`.
- Соблюдение плана: `adherence = доля направлений в допуске` (0…1).
- Итог периода: `mandatoryCovered = факт по обязательным > 0`; `savingsMet = факт накоплений ≥ план`.

**Доход и награды (RewardEngine):**

- `START_BALANCE = 40` (первый период, доход не начисляется).
- `WEEKLY_INCOME = 30` — автоматически в начале каждой следующей недели.
- Награда за задание: `reward = base + 2`, если все шаги выбраны верно (`ALL_CORRECT_BONUS = 2`).

**Накопления и цель (SavingsEngine):**

- Пополнение: в пределах доступного баланса.
- Снятие: только после подтверждения (preview показывает `newSavings`, `newBalance`, `goalRemainder`, `periodsToGoal`).
- Прогноз срока: `periodsToGoal = ceil((price − savings) / avgDeposit)`; `avgDeposit` — среднее фактическое пополнение за последние 3 закрытых периода (минимум 10 монет на период).

**Состояние и рост питомца (PetEngine):**

- Показатели: настроение (mood) и сытость (satiety), диапазон 0…100; базовый максимум 100, потолок `MAX_CAP = 150` (повышается предметами «Улучшения» на их бонус +10/+10/+10/+10/+15).
- Штраф за непокрытые обязательные расходы в конце периода: `mood −15`, `satiety −20` (обратимо: восполняется в следующих периодах).
- Бонус: при `adherence ≥ 0.99` — `mood +10`.
- Уровни предупреждения: показатель ≤ 10 — критическое (2), ≤ 20 — низкое (1).
- Проигрыш: `mood ≤ 0` или `satiety ≤ 0` → экран проигрыша с возможностью начать заново (формулировка нейтральная, без запугивания).
- Стадия за период: `score = 0.4 × mandatoryCovered + 0.3 × adherence + 0.3 × savingsMet`; «Друг» при среднем score ≥ 0.6; «Звезда» при среднем ≥ 0.8 и не менее 5 закрытых периодов. Стадия не понижается.
- Победа: покупка всех 5 ключевых улучшений (доступны строго по порядку) → экран победы.

**Экономика контента:** 8 продуктов (восполняют сытость/настроение: +10…+15 к показателю), 5 улучшений (цены 10/15/20/30/40, поднимают максимум и не восполняют), 3 цели (60/100/150 монет). Все значения — в JSON, расширение не требует правки кода.

## 7. Карта образовательного контента

15 заданий, файл `app/src/main/assets/content/tasks.json`. Три темы: **BUDGET_PLANNING** (планирование бюджета), **SAVINGS** (накопления), **PURCHASES** (покупки). Задания с `ageGroup: 1` — усложнённые для 10–11 лет (3 шага, счёт в 3 действия, деление с остатком). Каждый вариант ответа сопровождается объяснением для ребёнка; неверный выбор — тоже учебная ситуация (объяснение ошибки, штраф к показателям, задание можно пройти повторно). Лимит: 1 задание на тему в день.

| ID | Тема | Возраст | Название | Сценарий | Ожидаемый навык (правильная логика) |
|---|---|---|---|---|---|
| task_budget_1 | Планирование | 7–9 | День рождения Финни | 30 монет; корм 12, шарик 10 | Сначала обязательное (корм), потом желаемое; остаток 30−12=18 хватает на шарик |
| task_budget_2 | Планирование | 7–9 | Три кармашка | 40 монет на 3 направления: еда 15, накопления 10 | Распределение по 3 направлениям: на желаемое 40−15−10=15 |
| task_budget_3 | Планирование | 7–9 | Приглашение в кино | Кино 12 при свободных 8 | Не занимать у накоплений; заложить кино в план следующей недели за счёт желаемых |
| task_budget_4 | Планирование | 7–9 | Распродажа | Мячик 8 вместо 12 при лимите 10 | Остаток 10−8=2; выгоду от скидки лучше добавить к накоплениям |
| task_savings_1 | Накопления | 7–9 | Мячик мечты | Цель 60, накоплено 20, откладываем по 10 | Остаток до цели 60−20=40; срок 40÷10=4 недели |
| task_savings_2 | Накопления | 7–9 | Дождливая неделя | Нужен дождевик 15, на накоплениях 30 | На обязательное можно взять из накоплений — осознанно и с планом вернуть; остаток до цели вырастет до 45 |
| task_savings_3 | Накопления | 7–9 | Рюкзак мечты | Цель 90, накоплено 50 | Остаток 40; срок 4 недели; не снимать накопления раньше времени |
| task_savings_4 | Накопления | 7–9 | Две мечты | Мячик 60 и велосипед 100, откладываем по 10 | Начинать с малой цели (6 недель), а не копить на обе сразу (12 недель) |
| task_purchases_1 | Покупки | 7–9 | Не хватает монет | Игрушка 20, в кошельке 15 | Баланс не в минус: не хватает 5; выход — заработать через задание |
| task_purchases_2 | Покупки | 7–9 | Что обязательное? | Корзина 45 при бюджете 30 | Обязательное — корм и витамины (25), помещается; желаемое откладываем |
| task_purchases_3 | Покупки | 7–9 | Последние монетки | Осталось 6 монет | Радость по средствам: наклейки за 5; сравнение «цены радости» (мячик 1.25 против наклеек 1.2 настроения за монету) |
| task_purchases_4 | Покупки | 7–9 | Два магазина | Мячик 12 рядом и 9 вдали | Полная стоимость: без дороги выгоднее 9; с транспортом 9+4=13 > 12 |
| task_budget_hard_1 | Планирование | 10–11 | Три недели подряд | Доход 30/нед., продукты 14, проездной 6, цель 8 | Многонедельный план: обязательные 20; свободные 30−20−8=2; за 3 недели накопится 8×3=24 |
| task_savings_hard_1 | Накопления | 10–11 | Две цели сразу | Домик 60 и наклейки 24, откладываем 12 (8 + остаток) | Приоритет главной цели: на вторую 12−8=4; наклейки через 24÷4=6 недель; домик через 60÷8=7 недель и 4 монеты (деление с остатком) |
| task_purchases_hard_1 | Покупки | 10–11 | Скидка или навязанное | Два пакета по акции 26 вместо 30 | Скидка реальна (4), но «акция на ненужное — это трата»: взять один пакет, остаток 15 — сначала накопления по плану, потом желаемое |

Каждое задание содержит: тему, возрастную группу, историю-вводную, 2–3 шага с вариантами выбора, эффекты к показателям питомца, объяснение к каждому варианту и награду (5–8 монет). Тексты согласованы с компетенциями Единой рамки финансовой грамотности (раздел 6 ТЗ).

## 8. Обоснование UX/UI-решений и доступность

**Ключевые решения:**

- **Главный экран — «всё сразу» (2.5.3):** питомец, баланс, накопления, цель, показатели и активное задание видны без навигации; ребёнок всегда понимает, сколько у него ресурсов.
- **Последствия решают на главном:** показатели питомца (полосы настроения/сытости с цветом **и** иконкой уровня) отвечают на вопрос «что мне дало решение»; итоги периода объясняют связь поступков и результата словами.
- **Ошибка — не тупик:** неверный ответ в задании даёт объяснение и небольшой штраф, покупка сверх баланса технически невозможна; план всегда можно пересобрать.
- **Этичность мотивации:** проигрыш формулируется нейтрально («Показатель дошёл до нуля — начнём заново»), без стыда и запугивания; нет таймеров и давления.
- **Возрастная адаптация:** задания для 10–11 лет сложнее (3 шага, деление с остатком), выбор возраста делается при создании питомца.
- **Единообразие:** последовательная навигация «назад», контрастные цвета категорий, цвет никогда не единственный носитель смысла (дублируется иконкой/подписью).

**Доступность (соответствие разделу 3.6 ТЗ):**

- Основной текст ≥ 16 sp; интерактивные элементы ≥ 48 × 48 dp (тема `core:design`).
- **Анимации можно отключить** — переключатель в разделе для взрослого (`anim_off`); критическая информация не передаётся только анимацией.
- Звуков в приложении нет — требование «звуки можно отключить» выполнено тривиально.
- Действия, заметно меняющие прогресс (сброс профиля, снятие накоплений), требуют подтверждения.

## 9. Разрешения Android, состав данных, удаление профиля

- **Запрошенных разрешений: 0.** В AndroidManifest нет ни одного `<uses-permission>` — приложению не нужны интернет, камера, микрофон, геолокация, контакты, Bluetooth. Основной цикл работает офлайн (требование 3.1.5).
- **Собираемые данные:** только локальный игровой профиль (имя питомца, выбранный персонаж, игровые числа: баланс, накопления, показатели, история транзакций). Никаких аккаунтов, ПДн ребёнка или взрослого, платёжных и банковских данных, рекламы, внутриигровых покупок и внешних ссылок (раздел 3.5 ТЗ). Всё хранится в локальной БД на устройстве.
- **Удаление профиля:** раздел для взрослого (AdultScreen) → «Сбросить прогресс» с подтверждением; также удаляются все данные стандартным способом: Настройки Android → Приложения → «Питомец Финни» → Очистить данные / Удалить.
- **Секреты:** keystore подписи и пароли в репозитории отсутствуют (требование 3.4).

## 11. Известные ограничения прототипа и план развития

**Ограничения текущей версии (v0.6.0):**

- Один локальный профиль на устройстве; многопрофильность и родительский веб-кабинет не реализованы (допустимо по границам MVP, раздел 2.7 ТЗ).
- Портретная ориентация на экранах от 360 dp; планшетная/альбомная раскладка не оптимизированы.
- Контент фиксированного объёма: 15 заданий, 13 товаров, 3 цели (выше минимума ТЗ, но без процедурной генерации).
- iOS-версия и серверная часть отсутствуют (в обязательный минимум не входят).
- Публикация в RuStore не выполнялась в рамках хакатона; сборка подготовлена к публикации (подписанный APK, minSdk 26, ноль разрешений).
- Проверка на физическом устройстве — по чек-листу раздела 10 (ожидает прогона на устройстве владельца).

**План дальнейшего развития:**

1. Публикация в RuStore (карточка подготовлена: `RuStore_карточка_черновик.md`).
2. Расширение контента через JSON без пересборки логики: новые задания, товары, цели, глоссарий.
3. Несколько локальных профилей на устройстве.
4. Адаптация под планшеты и альбомную ориентацию.
5. Дополнительные достижения и событийные периоды (праздничные недели).
6. При необходимости — iOS-версия на KMP/Compose Multiplatform.
