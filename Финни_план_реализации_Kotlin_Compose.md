# «Питомец Финни» — план реализации на Kotlin + Jetpack Compose

Функциональный прототип Android-приложения для формирования финансовых навыков у детей 7–11 лет.
Соответствие ТЗ: локальный профиль без регистрации, офлайн-режим, демонстрационный режим,
подготовка к публикации в RuStore. Серверная часть не используется.

---

## 1. Технологический стек и окружение

| Компонент | Выбор | Обоснование |
|---|---|---|
| Язык | Kotlin 2.x, JVM 17 | Официальный стек Android |
| UI | Jetpack Compose (Material 3) | Декларативное состояние, анимации питомца |
| Архитектура | MVVM + однонаправленный поток данных (UiState + события) | Тестируемость, простая логика для демо |
| DI | Hilt | Стандарт, минимум шаблонного кода |
| БД | Room (SQLite) | Типобезопасная схема профиля и истории периодов |
| Настройки | DataStore Preferences | Флаги (демо-режим, звук, тестовый профиль) |
| Сериализация контента | kotlinx.serialization | JSON-контент в assets |
| Тесты | JUnit 5 / kotest, Turbine (для Flow) | Покрытие игровой экономики |
| Мин. SDK | 26 (Android 8.0) | По ТЗ п. 3.1 |
| Сборка | Gradle Kotlin DSL, `assembleRelease` | Воспроизводимость, ключ подписи вне репозитория |

Разрешения Android: **никакие не запрашиваются** (в ТЗ все функции работают офлайн и без железа).

## 5. Формулы игровой экономики

Все формулы — в `core/economy/`, покрыты юнит-тестами (требование п. 3.4).

### 5.1. План бюджета
```
Сумма плана = planMandatory + planOptional + planSavings
Контроль:  Сумма плана ≤ balance, иначе блок + подсказка, чего не хватает
Остаток = balance − Сумма плана          (показывается ребёнку при планировании)
```

### 5.2. Покупка
```
if (price > balance) → отказ: "Не хватает X монет. Варианты: отложить, выбрать дешевле,
                          заработать в задании, перенести необязательную покупку"
else balance -= price; fact<категория> += price; применить эффект к состоянию
```

### 5.3. Накопления и срок цели
```
Пополнение:   savings += X; balance -= X     (внутри периода идёт в factSavings)
Снятие:       только после подтверждения; до подтверждения показать
              savings' = savings − X и новый срок
Срок цели = ceil((price − savings) / среднее пополнение за период)  в игровых периодах
```
Среднее пополнение = среднее factSavings за последние 3 закрытых периода (или факт текущего, если данных мало).

### 5.4. Награды
```
Доход за задание: reward (из tasks.json), начисление = транзакция INCOME_TASK с источником
Ежедневный доход: base = 20 монет, но в ДЕМО-режиме выдаётся по кнопке «Следующий день»
Бонус от взрослого: 0–10 монет, вручную, с подтверждением взрослого (механика команды)
```

### 5.5. Состояние питомца (настроение, сытость)
```
mood'   = clamp(mood   + Σэффекты покупок + Σэффекты заданий, 0..100)
satiety'= clamp(satiety+ Σэффекты еды,                        0..100)
```
Обязательные покупки не куплены к закрытию периода → mood −15, satiety −20 (обратимо, без «смерти»).

### 5.6. Стадии развития (≥3 стадии)
```
score = 0.4·(доля периодов с закрытыми обязательными расходами)
      + 0.3·(доля периодов, где |факт−план| ≤ 20% по каждому направлению)
      + 0.3·(доля периодов с factSavings ≥ planSavings)
stage = 0 (Щенок) → 1 (Подросток) при score ≥ 0.6 → 2 (Звезда) при score ≥ 0.8 за 5 периодов
```
Стадия никогда не понижается ниже достигнутой («безопасная ошибка» — прогресс не обнуляется).
После каждого изменения — короткое объяснение: «Финни вырос! Ты 4 периода подряд откладывал на цель».

## 6. Демонстрационный режим (критично для экспертизы)

- Включается в разделе взрослого; флаг — в DataStore.
- Убирает календарные ожидания: ежедневный доход выдаётся по кнопке «+день», задания открыты сразу (п. 2.5.8).
- Кнопка «Сбросить тестовый профиль»: возвращает профиль к исходному состоянию (стартовый баланс, stage 0, чистая история) — перепроход шагов 1–12 заново.
- Тестовый профиль помечается `isTestProfile = true`, чтобы эксперт видел, что данные не «боевые».
- Игровой период в демо-режиме закрывается по кнопке «Завершить период», а не по таймеру.

## 7. Тестирование

1. **Юнит-тесты (`core/economy/`)**: контроль лимита плана, отказ покупки при нехватке, снятие с накоплений без подтверждения, пересчёт стадии, срок цели. Минимум 25 кейсов.
2. **Интеграционные**: Room-миграции, сохранение после «закрыть приложение → открыть» (шаг 11 ТЗ).
3. **Ручной чек-лист на физическом устройстве** (RAM ≥3 ГБ, Android 8+): запуск ≤5 с, отклик ≤1 с, отсутствие падений на шагах 1–12, офлайн-работа.
4. **Матрица соответствия ТЗ** (п. 5 документации): требование → статус → экран/модуль/тест.

## 10. Риски и ограничения

- Контент (сценарии заданий, рисунки питомца) — главный объём работ; смягчение: модульный питомец из 3 частей, генерация/свободные ассеты с фиксацией лицензий.
